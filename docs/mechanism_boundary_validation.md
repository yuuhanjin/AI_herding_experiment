# 价格机制边界：离线验证与做市商提示词对照

日期：2026-10-15。对象为 arXiv:2504.10789 的 Figure 6–7 无限期、15 轮、$56/$14 起点情景。这里测试的是当前仓库的机制，不是论文历史代码的严格复跑。原始基线见 [replication_status.md](replication_status.md)。

## 概念和论文主张

基本价值是按预期每轮股息与利率计算的基准：`E[D]/r = $1.40/0.05 = $28`。初始价 $56 是基本价值的两倍（高估 100%）；$14 是其一半（低估 50%）。两个偏离幅度并不对称。论文另外描述 $35/$21、20 轮的有限期情景；Figure 6–7 用的是 $56/$14、15 轮、无终期赎回的无限期情景。论文文字结论：从 $56 出发未在 15 轮内收敛到 $28；从 $14 出发则明显向 $28 收敛，个体估值也向基本价值调整。[论文 §3.1–3.2.3](https://arxiv.org/html/2504.10789)

- **记录价格 `price`**：当前引擎有成交就取本轮最后一笔成交价；无成交时取订单簿报价（通常是最优卖价），再不行才延续前价。它不等于严格的成交价序列。
- **midpoint**：同一时刻最优买价（bid）与最优卖价（ask）的平均值；缺任意一边就没有 midpoint。它是报价指标，不是实际成交价。
- **last executed trade**：市场里真正撮合成功的最后一笔交易的价格；没有任何真实成交时应记为缺失，而不是初始参考价。若画连续线，可以另行定义“起点参考价向前延续”，但必须标明这是派生口径。

论文列出 transaction price、midpoint 和 spread 等可分析指标，但 Figure 6 的图注只称“price evolution”，未交代它实际采用哪一条价格序列；因此本次不能假定 Figure 6 与当前 CSV 的 `price` 完全同口径。[论文 §2.3.4、Figure 6](https://arxiv.org/html/2504.10789)

## 边界一：没有成交也能改价——已直接验证

基线 $56 情景的 103 笔已接纳订单全是卖单，15 轮零成交；记录价格终点 $46。无买盘时，未成交市价卖单可转成相对参考价低 10% 的限价卖单，而无成交定价选择最优卖价。测试 [`test_price_mechanism_audit.py`](../tests/test_price_mechanism_audit.py) 重现了 `$56 → $50.40` 且成交列表为空的路径。因此这条记录线不能证明交易驱动的向下价格发现。新对照中，$56 情景的 120 笔已接纳订单仍全为卖单，零成交，终点 $50.40；边界仍存在。

## 边界二：增加卖单不自动导致向 $28 收敛——对照支持

唯一处理是把做市商 system prompt 中三处借券/做空表述改为“只能卖自有股份”；情景参数、其他 agent 的 system prompt、撮合及资金规则未改。比较数据：

| 指标 | 原基线 $56 | 提示词对照 $56 | 原基线 $14 | 提示词对照 $14 |
| --- | ---: | ---: | ---: | ---: |
| 第 15 轮记录价 | $46.00 | $50.40 | $15.35 | $15.30 |
| 真实成交笔数 / 股数 | 0 / 0 | 0 / 0 | 23 / 13,999 | 24 / 22,000 |
| 已接纳买单 / 卖单 | 0 / 103 | 0 / 120 | 172 / 17 | 123 / 40 |
| 卖方做市商人数 | 2 | 2 | 1 | 2 |
| 最终同步期末 midpoint | 不存在 | 不存在 | 旧日志未记录 | $15.075 |

低价对照的卖单数量翻倍有余，真实成交量增加，但卖价仍集中在 $14.42–$15.45 附近，远低于 $28。$14→$15.30 的记录价上涨中，$0.88（67.7%）发生在零成交的第 3、5、11 轮。由此可排除“仅仅因为做市商提示词说允许做空，所以当前结果不收敛”这一**单一、充分解释**；更核心的可观察瓶颈是模型选择贴近现价挂单，买卖双方的边际价格没有靠近基本价值。这个解释是对四条具体路径的机制判断，不是跨随机种子的统计结论。

注意：两组虽都设 `RANDOM_SEED=42`，原基线与新对照的实际股息路径不同（$56 对比在 8 个支付轮不同；$14 对比在 2 个支付轮不同）。全局随机数还用于 agent 和订单洗牌。因此不能把两个终点价格差 $0.05/$4.40 归因于提示词的因果效应；需要独立固定股息随机流并重复多种子后才能估计效应。`structured_decisions.csv` 记录的是模型提出的订单；`order_data.csv` 是已接纳订单，二者数量不应直接视为相同。`validation_errors.csv` 为零不代表所有订单都通过资金/持仓校验。

## 记录口径修正与尚未解决的问题

当前 `market_data.csv` 的旧 `best_bid/best_ask` 是撮合前快照，`price` 是撮合后结果。新运行增记了 `pre_match_*`、`post_match_*` 与 `post_match_midpoint`，所以同步期末 midpoint 可以正确识别。**但这两次对照生成时新增的 `last_trade_price/last_trade_round` 列不能作为真实最后成交指标**：`SimulationContext.current_price` 的 setter 在无成交改价时也覆盖 `public_info['last_trade']['price']`。原始日志保留、不改写；真实最后成交须从 `trade_data.csv` 重建。后续运行的记录代码已改为从真实 `trade_history` 输出 `last_executed_trade_price/round`，无成交则为空。此记录修正尚未产生新的付费运行验证，但已有单元测试通过。

历史版本仍未对齐：现用 `paper_scenarios.py` 于论文提交之后加入仓库；当前做市商提示词与论文附录禁做空表述冲突，当前决策 schema 也从论文的单一 price target 演变成多期价格预测。本次处理只检验做空表述，并未重建论文完整历史环境。

**下一步**：先修复/隔离 `last_trade` 的语义和订单拒绝日志，给股息独立随机流，再做严格配对、多种子比较；在此之前不应改动订单撮合规则或把单次不一致称为论文反例。
